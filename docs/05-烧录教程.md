# 烧录教程（从零到跑起来）

> 目标：把 `qybridge` 刷进 ESP32-S3，并且确认它正常工作。
> 全程不需要装开发环境，**会用浏览器就行**。

---

## 0. 你需要什么

| 东西 | 说明 |
|---|---|
| ESP32-S3 开发板 | 16MB Flash（N16R8 常见款即可） |
| **USB 数据线** | 必须能传数据。纯充电线插上只会亮灯，电脑认不到串口 |
| 电脑 | Windows / macOS / Linux 都行 |
| 魔方 + 手机 | 只有验证阶段需要；烧录本身不需要 |

---

## 1. 三种方式，先选一种

| 方式 | 适合谁 | 需要装什么 |
|---|---|---|
| **A. 网页烧录** | 大多数人，最省事 | 只要 Chrome 或 Edge |
| **B. 命令行 esptool** | 要批量刷、要脚本化 | Python + `esptool` |
| **C. 源码编译** | 想改代码 | ESP-IDF v6.0.1（见 README） |

下面 A、B 两种都只烧**预编译好的固件**，不改代码。

---

## 2. 方式 A：网页烧录（推荐）

### 2.1 先确认电脑认到了板子

1. 用**数据线**把板子插到电脑；
2. Windows 打开 **设备管理器 → 端口 (COM 和 LPT)**，应该多出一个
   `USB 串行设备 (COMx)` 或 `Silicon Labs CP210x (COMx)` / `CH340 (COMx)`；
3. 记住这个 COM 号（例如 `COM6`）。

> ⚠️ **不要选名字里带"蓝牙"的串口**（例如"蓝牙链接上的标准串行"）。
> 那是虚拟串口，选它一定连不上。

**双 Type-C 口**的板子：优先插标着 **COM / UART** 的那个口；
实在认不到就换另一个口再试。

### 2.2 打开网页工具

用 **Chrome 或 Edge** 打开 <https://esptool.spacehuhn.com/>。

> Safari / Firefox 不支持 Web Serial，用不了。

### 2.3 连接板子

1. 点 **Connect**；
2. 浏览器弹出串口列表，选刚才那个 COM 口；
3. 等网页识别芯片，**确认显示的是 ESP32-S3**。

### 2.4 选择固件 + 填地址

1. 从本仓库的 [Releases](../../releases/latest) 下载 `qybridge-esp32s3-merged.bin`；
2. 在网页的文件列表里选中它（列表为空就点 **Add** 添加一行）；
3. **把该行的地址（Offset）改成 `0x0`**。

> 🔴 **地址必须是 `0x0`，不是 `0x10000`。**
> `merged` 镜像里已经拼好了 bootloader、分区表和应用，从 0 开始烧。

### 2.5 开始烧录

点 **Program**，等进度条到 100%、显示完成。

- 烧录过程中**不要拔线、不要关网页**；
- 4MB 左右的数据，通常 10~30 秒。

### 2.6 让它跑起来

烧完网页会自动复位。如果没有：

- 按一下板子上的 **RST / EN** 键，或
- 拔插一次 USB。

## 3. 方式 B：命令行（Windows / macOS / Linux）

```bash
pip install esptool

# 查串口：Windows 看设备管理器；macOS: ls /dev/cu.*；Linux: ls /dev/ttyUSB*
esptool.py --chip esp32s3 -p COM6 -b 460800 write_flash 0x0 qybridge-esp32s3-merged.bin
```

- 把 `-p COM6` 换成你自己的串口（Linux/macOS 如 `/dev/ttyUSB0`）。
- 波特率 `460800` 失败时降到 `115200` 再试。
- **只想更新应用、保留配对记录**（不清 NVS）：

  ```bash
  esptool.py --chip esp32s3 -p COM6 -b 460800 write_flash 0x10000 qybridge-esp32s3.bin
  ```

- **整片擦除**（怀疑固件或 NVS 坏掉时）：

  ```bash
  esptool.py --chip esp32s3 -p COM6 erase_flash
  ```

`merged` 与 `app` 两个文件的区别：

| 文件 | 烧录地址 | 覆盖内容 | 什么时候用 |
|---|---|---|---|
| `qybridge-esp32s3-merged.bin` | `0x0` | bootloader + 分区表 + 应用 | 首次烧、换版本、救砖 |
| `qybridge-esp32s3.bin` | `0x10000` | 只有应用 | 只更新程序，**保留配对记录** |

> ⚠️ 烧 **merged** 会覆盖 NVS（保存着配对的魔方地址），
> 所以烧完要重新"转一下魔方"让它重新发现。用 app 更新则不需要。

## 4. 连不上 / 报错怎么办

### 4.1 进不了下载模式

很多失败其实是**板子没进下载模式**。手动进：

1. **按住 BOOT**（有的板标 `IO0` 或 `BOOT`）；
2. **点一下 RST / EN**；
3. **松开 BOOT**；
4. 再点 Connect / 重新执行命令。

### 4.2 报错对照表

| 现象 / 报错 | 原因 | 处理 |
|---|---|---|
| 串口列表为空 | 线是充电线 / 没装驱动 / 口插错 | 换数据线；装 CH340 或 CP210x 驱动；换另一个 Type-C 口 |
| `Could not open port 'COMx'` | 串口被别的程序占着 | 关掉串口助手、Arduino 串口监视器、网页烧录页面 |
| `Failed to connect to ESP32-S3` | 没进下载模式 | 按 §4.1 手动进下载模式 |
| `Wrong boot mode detected` | 同上 | 同上 |
| 烧录到一半失败 | 线材/供电/USB 口不稳 | 换线换口；波特率降到 `115200` |
| 烧完没反应 | 还在下载模式 | 松开 BOOT，按一下 RST |
| 能烧但灯不闪 | 板子灯不在 GPIO48 | 见 README「常见问题」，改 `move_led.c` 的引脚 |
| 手机搜不到 `QY-QYSC-S-XXXX` | 广播没起来 / 权限没给 | 看串口有没有 `广播中`；开手机蓝牙与"附近设备"权限 |

## 5. 烧完怎么确认成功

### 5.1 看串口（最可靠）

用任意串口助手 / `idf.py monitor` / `python tools/serial_capture.py COM6 20`，
波特率 **115200**。正常启动会依次出现：

```
固件: qybridge 1.0.0 (MoYu WCU -> QiYi QYSC)
虚拟奇艺魔方 QY-QYSC-S-XXXX 地址 CC:A3:00:00:XX:YY
===== 自检全部通过 =====          ← 关键：必须是"全部通过"
广播中: QY-QYSC-S-XXXX
```

看到 `自检全部通过` 就说明固件本身没问题，剩下的只是连接问题。

### 5.2 看手机

手机蓝牙里能搜到 `QY-QYSC-S-XXXX`，在奇艺 App 里连上即可。

### 5.3 看灯

**上电后灯不亮是正常的** —— 它只在"转译了一个动作"时闪。
转一下实体魔方，每转一步板子应当闪一下。

---

## 6. 出问题怎么救回来

1. **怀疑固件坏了**：`erase_flash` 之后重烧 merged 镜像；
2. **想退回上一版**：重新烧上一版的 `merged.bin`（比如 `v1.0.0`）；
3. **板子一直重启**：先 `erase_flash`，再烧 merged；
4. **完全认不到串口**：换线、换 USB 口、换电脑，最后才考虑板子损坏。

---

## 7. 现场救场记住三件事

1. **地址填 `0x0`**
2. **必须用数据线**
3. **烧完拔插一次 USB（或按 RST）**
