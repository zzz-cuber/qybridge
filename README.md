# qybridge · 魔域智能魔方 → 奇艺 Smart Player Pro 协议网关

**让魔域（WCU）的智能魔方，出现在奇艺（QiYi）的 App 里，并且用起来和真机一样。**

一块 ESP32-S3，同时扮演两个角色：

```
魔域魔方  ──BLE 主机──►  ESP32-S3  ──BLE 外设──►  奇艺 App
(WCU 协议)              转译引擎              (QYSC 协议)
```

跑在 ESP32-S3 上（ESP-IDF v6.0.1 + NimBLE 双角色），现场只需一块开发板 + 一根线，
不需要电脑。

---

## 为什么需要它

智能魔方三大品牌各有一套封闭生态，App 之间互不相通：

| 品牌 | 产品 | App |
|---|---|---|
| GAN | 魔方星球 | GAN 协议 |
| 魔域文化 | WCU CUBE | WCU（MY3 / MY32）协议 |
| 奇艺 | Smart Player Pro | QYSC 协议 |

如果你的比赛/训练平台只认奇艺 App，而你手上是魔域的魔方——本项目就是这一层桥。

**它做的事只有一件**：把实体魔方的动作流，逐条翻译成奇艺 App 听得懂的动作流。

## 实测状态

真机：ESP32-S3 N16R8 + 魔域 `WCU_MY32_CD35` + 奇艺 Smart Player Pro。

| 验收项 | 结果 |
|---|---|
| 8 组上电自检 | ✅ 全部通过 |
| 手机搜到并连接 `QY-QYSC-S-XXXX` | ✅ MTU 协商到 99 |
| 跟随实体魔方转动 | ✅ 364 步 → 364 帧，编号连续 |
| 快速连拧（约 6~24 TPS 的抽测段） | ✅ 无丢步、无队列溢出 |
| 打乱 → 复原 → 出成绩 | ✅ 连续 3 把 |

## 快速开始

### 1. 烧录（不需要开发环境）

**完整教程（驱动、串口识别、进下载模式、报错排查）见
[`docs/05-烧录教程.md`](docs/05-烧录教程.md)。** 这里是最短路径：

1. 从 [Releases](../../releases/latest) 下载 `qybridge-esp32s3-merged.bin`；
2. 用 **USB 数据线**（不是充电线）把板子插到电脑；
3. 用 Chrome/Edge 打开 <https://esptool.spacehuhn.com/> → **Connect** → 选串口
   （**别选名字带"蓝牙"的那个**）；
4. 文件选刚下载的 bin，**地址填 `0x0`**；
5. 点 **Program**，等进度到 100%；
6. 烧完**拔插一次 USB**（或按一下 RST / EN），板子开始运行。

命令行等价操作：

```bash
esptool.py --chip esp32s3 -p COM6 -b 460800 write_flash 0x0 qybridge-esp32s3-merged.bin
```

**烧完怎么确认成功**：串口（115200）应打印
`===== 自检全部通过 =====` 和 `广播中: QY-QYSC-S-XXXX`；上电时灯不亮是正常的，
只有转译动作时才闪。

> ⚠️ 合并镜像会**覆盖 NVS（配对记录）**，烧完要重新"转一下魔方"让它重新发现。
> 只想更新应用、保留配对：把 `qybridge-esp32s3.bin` 烧到 `0x10000`。

### 2. 使用

1. USB 供电即可（现场用充电宝也行）；
2. **转一下实体魔方**唤醒它，放到板子旁边 —— 板载灯不闪就说明没连上；
3. 手机打开奇艺 App → 连接魔方 → 搜索 → 连 **`QY-QYSC-S-XXXX`**；
4. 转魔方，App 里的 3D 魔方应当同步跟随，并且**每转一步板子闪一次**。

App 里的 **「复原重置」** 按钮不仅复位虚拟魔方，还会通过 **`0xA2`** 让实体魔方
内核也回到复原态（可通过串口命令 `policy` 关掉）。

## 自己编译

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p COM6 flash monitor
```

或使用 `build.ps1`（Windows）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Flash -Port COM6
```

> `build.ps1` 里的工具链路径按作者本机写死，换机器改开头几行即可。

⚠️ **两个路径坑**（实测会卡住构建）：

1. **工程路径不能有空格** —— ESP-IDF 的 `component_requirements.py` 会报
   `cannot match original component filename`。
2. **不能用中文路径**。

## 串口控制台（115200）

```
state     打印本地状态 / 连接情况
stats     统计：转译步数、丢步、中层转、App 强制状态、模型核对
test      重新跑一遍自检（逐项打印）
rescan    重新扫描实体魔方
clear     清除配对记录
reset     给实体魔方下发 0xA2
resync    强制重新同步（丢步后用）
policy    开关"App 复原重置 → 实体魔方重置"
hist N    历史区模式 0..3（排查"一转就乱"用，见 docs/02 第 8 节）
move N    偏移 34 转动码开关（排查用）
log       切换日志级别
```

## 自检：不用手机和魔方就能验证

上电自动跑一遍，串口打印 `===== 自检全部通过 =====`。它盯的是**最容易错、
错了就必然 DNF** 的地方：

1. CRC16 已知向量、AES 往返；
2. 复原态 27 字节与协议文档**逐字节一致**；
3. 12 个转动码与文档表逐个对照；
4. `StateChange` 帧每个偏移、历史区、CRC 余数；
5. `(R U R' U')^6 = 恒等`、`T-perm^2 = 恒等`（转动表与复合顺序）；
6. 贴纸串 ↔ cubie 往返；
7. 魔域 `0xA5` 位流解析（含 M/E/S 识别）；
8. 端到端：3 步打乱 + 3 步还原 → 6 帧，ack 与历史全部正确。

## 设计要点（为什么这么写）

| 原则 | 原因 |
|---|---|
| **一步一帧，不合并/不跳帧/不补发** | App 的动作模型是加法：少一帧，复盘就走不到复原态 →「步骤不完整」 |
| **本地状态只由动作流推进** | 中途用魔方快照覆盖会导致"虚晃一下又弹回"，并让动作与贴纸不自洽 |
| **发空历史区（全 `0xFF`）** | 实测：这个 App 会把历史区里的动作再走一遍，填了就"一转乱好几步" |
| **失败要响，不要静默** | 丢步 / 收到 M·E·S / 队列溢出 → 停机告警并请求重新同步 |
| **单一写者** | BLE 回调只投递事件，`runtime` 任务独占状态，不用锁 |

详见 [`docs/03-架构与不变量.md`](docs/03-架构与不变量.md) 与
[`docs/02-DNF根因分析.md`](docs/02-DNF根因分析.md)。

## 已知边界

* **中层转 M / E / S**：奇艺只有 12 个面转码，数学上无法表达（会带走中心块）。
  实体魔方通常自己把 M 拆成两个面转上报，照抄即可；若真收到 `code ≥ 12`，
  固件会停机告警而不是静默丢帧。**解法请避免 M 层公式。**
* **魔域有两代协议**（v4 用 cubie 布局 / v5 用 3bit 贴纸）。本项目按 **v5** 实现；
  v4 魔方会报状态解析失败。
* 只实现**魔域 → 奇艺**一个方向；编解码与转译核心是分层的，接别的品牌只需新增
  一对 codec。

## 常见问题

| 现象 | 处理 |
|---|---|
| 手机搜不到 `QY-QYSC-S-XXXX` | 确认串口打印了 `广播中`；手机蓝牙与"附近设备"权限要开；附近别同时有第二个奇艺魔方 |
| 连上但几秒就断 | 看 MTU：96 字节帧需要 **MTU ≥ 99** |
| App 里魔方不动 | 看有没有 `[mv n]`；没有说明实体魔方没连上（`state` 查看），转一下唤醒它 |
| 弹「本次复原步骤不完整」 | 查日志里的 `丢步` / `收到中层转` / `[verify] 不一致`，并保留那一把的完整日志 |
| 板载灯不闪 | 引脚不对（不同板子可能是 GPIO38 或单色灯），改 `move_led.c` 里的 `MOVE_LED_GPIO` |
